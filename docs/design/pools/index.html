Node pool view: design options

Which pods run in each node pool, their namespaces, and how much of each node's allocatable CPU and memory each pod requests (as in kubectl describe node).

Chosen: B: Capacity map, minimal scope. The other options are kept as a record.

  1. A: Pool → node accordion: totals at each level, with a describe-style pod table per node.
  2. B: Capacity map: stacked per-pod segments coloured by namespace, so the big consumers stand out.
  3. C: Namespace × pool matrix: which namespaces run where, and how much they take.
